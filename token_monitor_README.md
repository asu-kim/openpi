# OpenPI Action & Security Monitor (`openpi_monitor.py`)

`openpi_monitor.py` mediates decoded continuous actions generated by the $\pi_0$-FAST Vision-Language-Action model. It classifies the first 10 executable actions using both intra-chunk and inter-chunk motion, routes significant actions through IoTAuth, routes insignificant actions through a separate plaintext channel, and records the resulting latency.

---

## 1. Key Features & Architecture

1. **Decoded Joint Motion Analysis**:
   - In live execution the monitor receives the continuous 14D ALOHA action array directly from the policy wrapper; JSONL is used for logging and offline analysis.
   - Intra-chunk motion is the maximum joint peak-to-peak range over the first 10 actions.
   - Inter-chunk motion is the maximum joint displacement between the current observed state and the first new action.
   - The maximum of these scores produces **`SIGA`** (Significant Action) or **`INSIGA`** (Insignificant Action).
2. **Dynamic Motion Thresholds**:
   - Tune sensitivity on the fly without editing code using the `--motion-threshold` CLI flag or the `OPENPI_MOTION_THRESHOLD` environment variable.
3. **IoTAuth Security & Session Key Caching**:
   - For `SIGA`, the monitor checks if an IoTAuth session key is cached and valid (verifying both absolute and relative validity timestamps).
   - If missing or expired, it opens an authentication socket to the Auth Server (using the entity configuration in `client.config`), negotiates a new cryptographic session key, and caches it.
   - If authentication fails or motion is disallowed, the in-process compatibility path repeats the last valid executable action (or the current observed pose before the first valid action).
   - `SIGA` chunks are serialized, encrypted and authenticated on port 21100. `INSIGA` chunks are serialized but unencrypted on port 21102.
   - No application ACK is used. Both paths share one global record sequence; the actuator fails closed on missing, duplicate or out-of-order IDs.
4. **Real-Time Latency Logging**:
   - Starts `monitor_actuator_ms` when decoded-motion analysis begins and stops it when the first verified action reaches the actuator-driver boundary.
   - Writes exactly one actuator latency record per action chunk. Execution of the action and the remaining horizon are not included.

## 2. Prerequisites

### 1. Lightweight Virtual Environment
You can run this script in a standard Python virtual environment independent of heavy ML environments:

```bash
python3 -m venv venv
source venv/bin/activate
pip install numpy cryptography typing_extensions
```

### 2. Docker Requirement
- **Offline Testing / Analysis**: Docker does not need to be running if you are testing against an existing `.jsonl` file.
- **Live Online Monitoring**: Docker must be running so the VLA model actively produces token logs:
  ```bash
  docker compose -f examples/aloha_sim/compose.yml up --build
  ```

## 3. Command-Line Arguments & Environment Variables

### Command-Line Flags
| Flag | Required | Description |
| :--- | :---: | :--- |
| `--config-file` | **Yes** | Path to the IoTAuth entity config file (e.g., `/app/sst_config_creds/client.config`). |
| `--log-file` | No | Path to a specific `pi0_fast_tokens*.jsonl` file for offline testing. If omitted, watches `data/aloha_sim/token_logs/` for new files. |
| `--motion-threshold`| No | Motion threshold for joint peak-to-peak variation (default: `0.01` or `OPENPI_MOTION_THRESHOLD` env var). |
| `--execution-horizon`| No | Leading actions used for the motion verdict and execution boundary (default: `10`). |

### Supported Environment Variables
| Environment Variable | Description |
| :--- | :--- |
| `OPENPI_MOTION_THRESHOLD` | Dynamically overrides the default joint motion threshold (`0.01`). Example: `OPENPI_MOTION_THRESHOLD=0.05`. |
| `FORCE_IOTAUTH_REQUEST` | When set to `1`, forces a fresh session key request for every SIGA record, bypassing cached keys. |
| `OPENPI_FAST_TOKEN_LOG` | Custom path/directory override for locating generated JSONL token log files. |
| `SECURE_ACTUATOR_ENABLED` | Set to `1` to enable the isolated dual-path actuator service. |
| `SECURE_ACTUATOR_HOST` / `SECURE_ACTUATOR_PORT` | Encrypted SIGA endpoint (default port `21100`). |
| `INSIGA_ACTUATOR_HOST` / `INSIGA_ACTUATOR_PORT` | Unencrypted INSIGA endpoint (default port `21102`). |
| `ACTUATOR_LATENCY_LOG` | Optional actuator-side JSONL path for `monitor_actuator_ms` records. `run_tests.sh --secure-actuator` configures this automatically. |

### Secure actuator gateway

Secure mode requires a separately registered Servers-group entity configuration. Start the gateway first:

```bash
python examples/aloha_sim/secure_actuator_gateway.py \
  --config-file /app/sst_config_creds/server.config
```

Then run the monitor/runtime with `SECURE_ACTUATOR_ENABLED=1`. The gateway uses
`accept_secure()`, so a missing session key is automatically retrieved from Auth by key ID.
The actuator process owns the Gym environment and one ordered execution queue. The runtime receives
observations over the control RPC on port 21101, and each tick carries the expected global record ID.
The first tick waits for that record for a bounded period. A missing, duplicate, skipped or
out-of-order record places the actuator in a fail-closed state and terminates execution with a
meaningful error. The complete model chunk is transmitted, while `execution_horizon` limits the
queue to the first 10 actions.

The actuator trusts the monitor's INSIGA classification and does not recompute the motion score.
Consequently, port 21102 is intended for trusted local IPC only and must not be exposed on an
untrusted network without adding authentication or an equivalent transport protection.

With generated monitor and server credentials, the complete Docker path can be started with:

```bash
export MONITOR_CONFIG=/app/sst_config_creds/local_auth/testing/validity/val1/client_val_1.config
export ACTUATOR_CONFIG=/app/sst_config_creds/local_auth/testing/validity/val1/server.config
export SECURE_ACTUATOR_ENABLED=1
docker compose -f examples/aloha_sim/compose.yml --profile secure-actuator up --build
```

The automated latency suite can enable the same path with `--secure-actuator`, for example:

```bash
./scripts/run_tests.sh --test1 --local --runs 1 --secure-actuator
```

When remote-Auth delay emulation is enabled, the runtime container installs the traffic-control
rule for the Auth endpoint in the shared host-network namespace. The same rule therefore covers
both the monitor's key grant request and the actuator's key-by-ID retrieval.

## 4. Usage Examples

### Mode A: Live Monitoring (Default & Recommended)
Watches the log directory for new inference files generated by the running simulation and monitors them in real time:

```bash
# Standard run with default threshold (0.01)
python openpi_monitor.py --config-file /app/sst_config_creds/client.config

# Custom threshold (0.05) using CLI flag
python openpi_monitor.py --config-file /app/sst_config_creds/client.config --motion-threshold 0.05

# Custom threshold and forced IoTAuth requests using environment variables
OPENPI_MOTION_THRESHOLD=0.05 FORCE_IOTAUTH_REQUEST=1 python openpi_monitor.py --config-file /app/sst_config_creds/client.config
```

### Mode B: Offline Testing
Process an existing `.jsonl` file instantly without waiting for Docker:

```bash
LATEST_LOG=$(ls -t data/aloha_sim/token_logs/*.jsonl | head -1)
python openpi_monitor.py --config-file /app/sst_config_creds/client.config --log-file "$LATEST_LOG" --motion-threshold 0.02
```

## 5. Output Log Format

The token JSONL retains monitor classification data. Secure-actuator runs additionally create a dedicated actuator JSONL containing one driver-handoff measurement per chunk:

```json
{
  "record_index": 0,
  "time_unix": 1751410800.123,
  "time_iso": "2026-07-01T10:40:00.123000-07:00",
  "monitor_latency": 14.82,
  "motion_label": "siga",
  "motion_intra_ptp": 0.21,
  "motion_inter_delta": 0.08,
  "motion_combined_score": 0.21,
  "auth_request_ms": 6.17,
  "secure_connect_ms": 2.31,
  "secure_serialize_ms": 0.08,
  "secure_send_ms": 0.44,
  "action_horizon": 50,
  "action_dim": 14,
  "decoded_actions": [ ... ]
}
```

```json
{
  "record_id": 0,
  "observation_id": 0,
  "motion_label": "siga",
  "monitor_start_ms": 1784300000000,
  "driver_handoff_ms": 1784300000043,
  "monitor_actuator_ms": 43
}
```

Analyze both logs with:

```bash
python scripts/analyze_latency.py TOKEN_LOG.jsonl \
  --actuator-log ACTUATOR_LATENCY_LOG.jsonl
```

The resulting per-run text report lists every inference with its SIGA/INSIGA label, intra score,
inter score, combined score, and `monitor_actuator_ms`. Its final episode summary reports the
SIGA/INSIGA percentages, mean latency, and the absolute maximum record latency. The automated
suite then aggregates these text reports into a final CSV. For each condition, `WorstCase_ms` is
the maximum observed record latency across all runs, not an average of per-run worst cases. Graphs
are rendered only after writing and reading this CSV.
