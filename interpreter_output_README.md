# FAST Token Interpreter Output Guide

This document explains the mathematical metrics generated by the `interpret_fast_tokens.py` script. 

When the interpreter processes a raw record from the Pi0 VLA model, it extracts the FAST action tokens and computes a coarse, decode-free estimate of how much the robot intends to move. Because FAST uses frequency-domain compression (Discrete Cosine Transform + Byte Pair Encoding), we can estimate the complexity of the physical trajectory entirely by looking at the diversity of the token sequence.

## Output Schema

For each 1,024-token chunk (or "record", representing one 32-step action horizon), the interpreter outputs a JSON object containing the following 9 metrics:

```json
{
  "token_count": 1024,
  "unique_tokens": 15,
  "unique_ratio": 0.0146,
  "entropy_bits": 1.25,
  "normalized_entropy": 0.125,
  "dominant_token": 257023,
  "dominant_fraction": 0.85,
  "motion_proxy": 0.125,
  "motion_label": "still"
}
```

## Metric Definitions

### 1. `motion_proxy` (Float, 0.0 to 1.0)
This is the most important metric. It is an alias for `normalized_entropy`. It serves as a fast heuristic to determine the magnitude of intended motion without having to perform expensive inverse-DCT math to decode the actual joint angles.
* **Low Proxy (closer to 0.0)**: The robot is commanding almost no movement across all joints.
* **High Proxy (closer to 1.0)**: The robot is commanding highly complex, multi-joint movement.

### 2. `motion_label` (String)
A human-readable classification of the `motion_proxy` score based on hardcoded thresholds. This is the label consumed by the `openpi_monitor.py` security gatekeeper.
* `"still"`: `motion_proxy < 0.35` (Robot is idle)
* `"low"`: `0.35 <= motion_proxy <= 0.60` (Minor adjustments)
* `"active"`: `motion_proxy > 0.60` (Significant movement)

### 3. `entropy_bits` (Float)
The raw Shannon entropy of the token sequence, calculated as:
$$H(X) = -\sum p(x_i) \log_2 p(x_i)$$
This measures the mathematical "surprise" or randomness of the model's output. A higher number means the model is outputting a wider variety of vocabulary IDs to describe a complex physical trajectory.

### 4. `normalized_entropy` (Float)
The `entropy_bits` divided by the maximum possible entropy for a sequence of that length ($\log_2(\text{token\_count})$). This scales the entropy to a clean 0.0 - 1.0 range, making it robust against changes to the `action_horizon` or `action_dim`.

### 5. `unique_tokens` (Integer)
The absolute number of distinct vocabulary IDs present in the chunk.

### 6. `unique_ratio` (Float, 0.0 to 1.0)
The percentage of the chunk that is made up of distinct tokens (`unique_tokens` / `token_count`). A sudden spike in this ratio often indicates a sharp transition between complex behaviors.

### 7. `dominant_token` (Integer)
The exact PaliGemma Token ID that appeared most frequently in the chunk. When the robot is idle, this is almost always the model's learned "zero-motion" or padding token (e.g., `257023`).

### 8. `dominant_fraction` (Float, 0.0 to 1.0)
The percentage of the chunk that consists entirely of the `dominant_token`. When idle, this fraction is extremely high (often > 80%).

### 9. `token_count` (Integer)
The total number of FAST action tokens in the chunk. For ALOHA simulation, this is always `1024` (32 timesteps $\times$ 32 action dimensions).

## Why this works mathematically
The FAST tokenizer works in the frequency domain. If the robot's target trajectory is completely stationary, the signal has energy *only* in the DC (Direct Current) coefficient. All other high-frequency coefficients are zero. 

When quantized, this results in massive runs of repeated zeros. The BPE (Byte Pair Encoding) tokenizer compresses these repeated zeros into a very small number of highly-repeated vocabulary tokens (low entropy).

Conversely, a complex movement (like grasping a cup) excites many higher frequencies across multiple joints. This produces a wide variety of non-zero coefficients, forcing the BPE tokenizer to output a diverse string of different vocabulary tokens (high entropy).
